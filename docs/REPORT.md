# Report: current limitations of the plant-readiness prototype

**Date:** 2026-10-13
**Scope:** changes to `model_train.py` and `prediction.py` plus the new
supporting package, database, feedback workflow, tests and docs.
The ESP32-CAM / Cloudinary / OpenCV measurement pipeline
(`plant_measurement.py`) was **not modified**.

---

## 1. What the real data can and cannot support

The real dataset (`data/super_orange_growth_data_with_growth_rate.csv`)
contains **250 observations of 10 Super Orange plants** over 25 days
(2083-05-02..2083-05-26), columns `Date, Age_days, Plant_ID, Height_cm,
Growth_rate_cm_per_day`.

Verified facts from the import + analysis run:

| Check | Result |
|---|---|
| Rows imported | 250 / 250 (all preserved) |
| Plants | 10 (single species, no variety column) |
| Data-quality issues found | none (dates, heights, growth rates consistent) |
| Mean growth rate | 0.2967 cm/day (per-plant slopes 0.26–0.37 cm/day) |
| **Verified readiness events** | **0** |
| Transplant dates | 0 |
| 14-day outcomes | 0 |
| Canopy width / true-leaf columns | not present in the CSV |

**Consequence:** the real dataset contains no verified readiness dates and
no transplant outcomes, therefore **no supervised readiness countdown model
can be trained from it**. The system reports this explicitly:

> `Readiness prediction unavailable: verified readiness-event data is not yet sufficient.`

Minimum requirements for training (configurable in
`plantreadiness/config.py`): **≥ 4 independent plants and ≥ 6 labelled
readiness events** per model scope. Real data currently has 0 events, so
Level 1/2 real models do not exist.

**This system does not predict real biological readiness today.** It
records measurements, shows growth trends, collects readiness assessments
and 14-day feedback, and predicts a countdown only where validated labels
exist - currently only in the synthetic demonstration.

## 2. Features demonstrated ONLY with synthetic data

The following are exercised **exclusively** by simulated data whose rules
are documented assumptions in `plantreadiness/synthetic.py`, not discovered
botany:

| Feature | Status | Evidence source |
|---|---|---|
| Countdown prediction (days remaining) | **synthetic only** | demo model, MAE ≈ 0.1–0.7 days on simulated holdout |
| Species/variety Level-1 model selection | **synthetic only** | per-species/variety models trained from simulated cohorts |
| Level-2 broader-model fallback | **synthetic only** (real has no models) | global demo model |
| Retrain gate (candidate vs deployed on same holdout) | **synthetic only** | `model_train.py --mode demo --retrain` |
| Simulated readiness events / labels | **synthetic only** | generator's assumed readiness rule (height ≥ threshold AND age ≥ minimum) |
| 14-day survival/growth outcomes | **synthetic only** | assumed survival probabilities |
| MAE-in-days validation metrics | **synthetic only** | real data cannot be validated without labels |

Reported validation MAEs (e.g. 0.36 days global demo model) describe
**simulated data only** and must never be quoted as real-world accuracy.

## 4. Removed / replaced approaches (and why)

| Removed | Why it was invalid |
|---|---|
| Grok/xAI API "botanical criteria" as label source | LLM output is not ground truth; criteria (root cohesion, substrate, floral primordia) do not exist in the dataset |
| Hardcoded rule labels (Too Early/Peak Ready/Too Late) then claiming the model learned readiness | circular: accuracy measured against labels generated by the same rules |
| Synthetic record generation inside the real-data training path | mixes simulated and real evidence |
| Random train/test split over repeated observations | leaks the same plant into train and test |
| Root/substrate/leaf-count required features | not measured in the CSV (leaf count and stem width are optional DB fields, supplied by the camera pipeline) |
| `accuracy_score` on self-generated labels | meaningless for a regression target with unknown real labels |

The initial loop is now correctly called **supervised learning** (training
on recorded readiness events); it is not reinforcement learning.

## 5. Known limitations / future work

1. **No readiness labels yet.** Real countdown predictions require an
   explicit readiness assessment protocol (or documented experiment) that
   records `readiness_observed_date` + `readiness_definition_version` +
   `assessment_source`. Until ≥ 4 plants / ≥ 6 events exist for a
   species/variety, only Levels 3–4 apply.
2. **14-day feedback does not create readiness labels.** A good survival
   outcome shows the chosen transplant stage was *associated* with
   acceptable survival/growth; it does not reveal the exact day readiness
   began, and the code deliberately refuses to auto-convert it.
3. **Single species, no variety metadata** in the real CSV - species-aware
   machinery exists but variety-level real models are impossible today.
4. **Width/leaf features are imputed on the historical CSV**: stem width and
   true-leaf count are measured by the camera pipeline and supported by the
   schema, but absent from the historical CSV, so CSV-derived training rows
   fall back to imputation for those columns. Live camera observations supply
   the real values.
5. **Prototype-scale model selection**: simple baselines (mean, Ridge,
   Random Forest) with GroupKFold; no hyperparameter search, no
   probabilistic intervals beyond reported MAE ± std.
6. **Synthetic holdout is synthetic**: old-vs-new comparisons are only
   meaningful within the simulation; they validate software behaviour, not
   biology.
7. **No scheduler/cloud**: overdue reminders are shown when the CLI opens;
   nothing runs in the background by design for this first version.
8. **Growth-rate column sign**: negative stored growth rates (measurement
   noise) are preserved rather than clipped; they are flagged only when they
   disagree with height deltas by > 0.05 cm/day.

## 6. Test status

`python -m unittest discover -s tests -v` → **82 tests, all passing**:

- `tests/test_dates.py` – readiness target day arithmetic, +14-day due
  dates, unknown-target handling,
- `tests/test_feedback.py` – growth calculation incl. missing/deceased
  plants, duplicate feedback & observation protection, immutability after
  submission, overdue reminders,
- `tests/test_fallback.py` – Level 1→4 fallback order, unvalidated models
  skipped, synthetic requires explicit opt-in, registry separation,
- `tests/test_model.py` – plant-grouped CV leakage checks, artefact
  metadata completeness, retrain decision gate, CSV import fidelity/idempotency,
  synthetic generator reproducibility,
- `tests/test_integration.py` – real pipeline refusal + no synthetic
  fallback for real plants, full demo workflow, holdout never in training,
  source mixing check, reminder output.

No tests failed.
